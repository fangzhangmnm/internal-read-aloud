## 1. 一句话

月读的 piper 模型（`ayousanz/piper-plus-tsukuyomi-chan`）里，「每个音素念多长」原来完全由模型自己预测。现在改了一处计算图，加了一个输入，**可以逐音素指定时长，或者只在模型预测得太短的地方兜底**。不重训，模型体积不变（39.65 MB）。

## 2. 做了什么（已验证）

- **改图脚本**：检疫桶 `~/jupyter/third-party/piper-plus/dur-override-exp/make_dur_override.py`（用同目录上一级的 `refvenv/bin/python` 跑；和 `langemb-exp/make_split.py`、`make_preset.py` 同一路子）。
- **改出来的模型**：`~/jupyter/third-party/piper-plus/work/model-singing/tsukuyomi-dur-override.onnx`（只在本机，**没进模型仓、没打包**）。
- **原理**：导出的图里，时长是 `w = exp(logw) × mask × length_scale`（节点 `/Mul_3`），然后 `/Ceil` 取整、展开成帧（上游 `export_onnx.py:619-629`）。新加输入 `dur_override`：形状 `[1, 音素数]`，float32，单位 = 解码帧（256 个采样点 = 22050 Hz 下 11.6 ms）。**某个音素给正数就用这个数，给 0 就用模型自己的预测**。`durations` 输出不变，仍然报模型自己的预测（方便先看再改）。
- **验证**（同目录 `verify-dur-override.mjs`，用 `piper-node.mjs` 在 node 里跑出货的日语前端 + onnxruntime-web 1.30，噪声置 0 让两次可比）：
  1. `dur_override` 全 0 → 和原模型**逐样本相同**（最大差 0，长度相同）。
  2. 给了值 → 输出长度 = Σ ceil(给的帧数) × 256，**完全吻合**；`durations` 输出仍等于模型预测。
- 没验证的：浏览器 Worker 里跑（同一个 onnxruntime-web，按理一样，没实测）；中文句子（验证用的是日语句子）；任何听感。

## 3. user 的建议，和 AI 的落地草想（未拍板）

user：**主要让 AI（模型）预测，但是加一下吃字的护栏。**

AI 草想——护栏 = **逐音素的最短时长**：模型预测的时长照用，只有某个音素短于下限时，才把它抬到下限。

- **做法 A（零新模型，适合先做实验）**：用上面这份改过的模型，跑两遍：第一遍 `dur_override` 全 0，读 `durations` 输出；算出 `override[i] = durations[i] < 下限[i] ? 下限[i] : 0`；第二遍带着它合成。代价：推理两次。
- **做法 B（适合出货）**：再改一次图，加一个 `dur_floor` 输入，图里直接 `w = Max(w, dur_floor)`，一遍出结果。脚本照 `make-dur-override.py` 改几行即可。
- 下限怎么定：按音素类别（元音 / 辅音 / 鼻音 …）各一个帧数，可能还要跟语速走。**具体数值没有任何依据，不要编**；用实验定。
